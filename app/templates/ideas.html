Feature ideas

Ideas to improve the app for viewing runs and bugs. Pick what fits your workflow.

Runs & history

  • Pass rate over time — Dashboard widget or chart: e.g. Run 1 100%, Run 2 85%.
  • Run comparison — Select two runs and diff: which tests passed in one and failed in the other.
  • Run tags/labels — Tag runs (e.g. nightly, release-1.2) and filter by tag.
  • Copy run link — Share button that copies the run URL for Slack/email.
  • Bulk delete old runs — e.g. delete runs older than 30 days.

Bugs

  • Filters on Bugs page — Filter by run, by project, or by date range.
  • Sort options — Sort by most linked, by label A–Z, or by first seen.
  • Bug notes — Optional note per bug (e.g. Fixed in build 123).
  • Export bugs list — CSV/Excel of all unique bugs with run IDs and test counts.

Test analysis

  • Flaky test detection — Highlight tests that failed in one run and passed in another.
  • Slow tests — Sort or filter by duration; highlight tests above a threshold.
  • Full-text search — Search across all runs (nodeid, error messages) from the dashboard.

Reporting & export

  • Export run as HTML report — Single HTML file for archiving or sharing.
  • PDF export — One-click PDF of the current run for stakeholders.
  • Scheduled summary — Optional email digest: last 7 days summary.

UX

  • Dark/light theme toggle — User preference for theme.
  • Keyboard shortcuts — e.g. / to focus search, j/k to move between rows.
  • Dashboard summary — On main page: total runs, total tests, total unique bugs (with link to Bugs).

Integrations (future)

  • Jira / Azure DevOps — Show ticket status (Open, Done) from the tracker.
  • CI webhook — POST a run from CI; app creates the run and can notify (e.g. Slack) on failures.
